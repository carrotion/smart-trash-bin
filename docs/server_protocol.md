# 로봇 ↔ 서버 통신 규약 — 초안 0판 (2026-11-14, 설계 단계·구현 전)

서버와 연동해서 미션을 하기 위한 약속이에요. 로봇 쪽은 이 저장소, 서버 쪽은 서버 개발 담당이 맡고, 이 초안을 보고 서로 맞춥니다.
역할 경계는 `docs/agent_architecture.md`(1절 원칙, 7절 엣지 우선 설계)를 따릅니다.

## 1. 지키는 것

1. **로봇은 서버를 기다리지 않는다.** 서버가 없어도 하던 일을 계속하고, 서버에 보낼 것은 쌓아 뒀다가 나중에 보낸다.
2. **서버는 시키고, 판단은 로봇이 한다.** 명령을 받아도 로봇이 할 수 없는 상태면 이유를 붙여 거절한다. 거절할 수 있는 경우는 배터리, 비상정지 중, 자리 검사 실패, 금지 구역이다.
3. **안전은 로컬에서 한다.** 비상정지, 장애물, 속도 단위 조종은 서버를 거치지 않는다. 서버의 "멈춰"는 미션을 그만두게 하는 편의 기능일 뿐이다. 진짜 정지는 로봇의 비상정지가 한다.
4. **명령마다 고유 번호와 만료 시각을 단다.** 같은 번호를 두 번 받아도 한 번만 한다. 만료가 지난 명령은 하지 않는다(통신이 밀렸다가 한꺼번에 오는 경우 대비).
5. **받았음, 시작, 끝을 따로 알린다.** 명령을 보낸 쪽이 지금 어디까지 됐는지 알 수 있게 한다.

## 2. 길

- **Tailscale**을 쓴다. 집 안에서는 Wi-Fi로 직접 이어지고, 덧붙는 왕복 시간은 1 ms 미만이다(11-14 실측). 서버는 자기 Tailscale 주소에만 받는 곳을 연다.
- **HTTP POST + JSON**으로 주고받는다(서버 개발 담당 권장). 사진과 음성은 본문에 그대로 싣는다. 음성을 끊김 없이 흘려보내야 할 때 WebSocket을 따로 검토한다.
- **연결은 로봇이 건다.** 로봇은 받는 곳을 열지 않는다. 서버가 보낼 명령은 로봇이 **오래 기다리는 요청**(long-poll)으로 받아 간다. 기다리는 시간은 예를 들어 20초이고, 명령이 생기면 그 즉시 응답이 온다. 이렇게 하면 로봇 쪽 열린 포트가 없고, 통신이 끊겼다 돌아와도 로봇이 다시 요청하기만 하면 된다.
  - ⚠️ 확인할 것: long-poll로 명령이 전달되는 시간. 오래 기다리는 요청이 걸려 있으면 거의 왕복 시간이고, 끊겼다 다시 거는 사이에 오면 그만큼 늦는다. 시험용 받는 곳이 열리면 잰다.

## 3. 주고받는 것

| 방향 | 이름 | 언제 | 내용(초안) |
|---|---|---|---|
| 로봇 → 서버 | `status` | 주기적(예: 5초), 상태가 바뀌면 바로 | 지도 위 자세, 배터리 전압·단계, 모드(대기·미션·탐색·충전·비상정지), 하고 있는 명령 번호, CPU·메모리, 통신 상태 |
| 로봇 → 서버 | `event` | 일이 생기면 | 미션 도착·실패(실패 이유는 주행기 문구 그대로), 갇힘, 비상정지, 배터리 단계 변화, 보드 무응답 |
| 로봇 → 서버 | `infer` | 서버에서 판정할 때(엣지 우선 설계 7절) | 일 종류(사람 인식·말 알아듣기 등), 사진 또는 음성, **마감 시각**. 마감이 지나면 로봇은 답을 버리고 엣지에서 다시 한다 |
| 로봇 → 서버 | `ack` | 명령을 받거나 상태가 바뀔 때 | 명령 번호, `받음` / `거절(이유)` / `시작` / `끝(결과)` |
| 서버 → 로봇 | `command` | long-poll 응답으로 | 번호, 만든 시각, 만료 시각, 출처(음성·대시보드·에이전트), 명령과 인자 |

### 명령(초안)

| 명령 | 인자 | 로봇이 하는 일 | 거절하는 경우 |
|---|---|---|---|
| `go_to` | 장소 이름 또는 지도 좌표 | 저장 지도 위 그 자리로 간다(지금 `tools/mission_go.py`가 하는 일) | 배터리 1차 하한 아래, 비상정지 중, 자리 검사 실패, 목표가 금지 구역 안 |
| `return_home` | — | 출발점(충전 자리)으로 간다 | 비상정지 중 |
| `explore` | `start` / `stop` | 탐색을 시작하거나 멈춘다 | 저장 지도로 다니는 중(탐색은 지도를 새로 그릴 때만 한다) |
| `cancel` | 명령 번호(없으면 지금 하는 것) | 미션을 그만두고 그 자리에 선다. 비상정지가 아니다 | — |
| `say` | 문장 | 로봇 스피커로 말한다(스피커를 단 뒤) | — |
| `get_status` | — | 바로 `status`를 보낸다 | — |

- 장소 이름 목록은 아직 없다. 저장 지도에 이름 붙인 자리를 만드는 일은 따로 정한다. 그 전까지는 지도 좌표를 쓴다.
- 서버에서 속도 단위로 조종하는 명령은 두지 않는다(1절 3번).

## 4. 로봇에 마이크·스피커를 달기 전의 음성 시험 — 서버 장치로 (2026-11-14 사용자 결정)

로봇의 마이크와 스피커는 깊이 카메라를 달 때 함께 단다. 그 전에는 서버에 연결된 스피커와 마이크로 **"말 → 알아듣기 → 명령 → 대답"**을 시험한다. 로봇은 움직이지 않는다. 명령은 3절 형식으로 만들어 기록만 하고 로봇에 보내지 않는다.

**시험 문장**(사람이 실제로 말할 법한 것 — 같은 명령을 여러 말투로):

| 명령 | 예 |
|---|---|
| `go_to` | "주방으로 가", "안방 가 줘", "거실로 와" |
| `return_home` | "제자리로 돌아가", "충전하러 가" |
| `explore` | "집 지도 그려", "탐색 그만" |
| `cancel` | "멈춰", "그만해", "취소" |
| `get_status` | "배터리 얼마야", "지금 어디야" |
| 명령 아님 | 평소 대화, TV 소리 — 명령을 만들면 안 됨 |

**잴 것**:
1. **말 알아듣기 시간**: 말이 끝난 때부터 글자가 나올 때까지. 중앙값과 90%를 잰다. 모델은 faster-whisper small과 medium이고, GPU가 한가할 때와 바쁠 때를 각각 잰다.
2. **알아들은 정확도**: 문장마다 10번 이상 말해서 명령이 맞게 나온 비율을 본다. 조용할 때와 소리(TV·청소기 정도)가 있을 때를 나눠 잰다.
3. **명령 만들기**: 글자 → 명령 JSON. 간단한 규칙과 서버 LLM을 비교한다. 비교할 것은 시간과 정확도, 그리고 "명령 아님"을 명령으로 잘못 만든 횟수다.
4. **대답 음성**: 문장 → 소리가 나기 시작할 때까지의 시간(한국어 TTS).
5. **전체**: 말이 끝난 때부터 대답 소리가 나기 시작할 때까지.

**아직 정하지 않은 것**:
- 부르는 말(호출어)을 쓸지, 버튼을 누르고 말할지. 로봇에서는 호출어를 엣지에서 듣는 게 맞다(7절 가벼운 일). 서버 시험에서는 가장 쉬운 방식으로 한다.
- 합격 기준 숫자. 위 측정을 보고 사용자와 정한다.

## 5. 열린 것

- `status` 주기, long-poll 기다리는 시간, 명령 만료 기본값. 첫 값은 시험용 받는 곳에서 잰 왕복 시간을 보고 정한다.
- 로봇이 쌓아 둔 `event`를 다시 보낼 때의 순서와, 서버가 같은 것을 두 번 받는 문제. `event`에도 번호를 붙여 서버가 중복을 걸러 내는 방식을 검토한다.
- 인증: Tailscale 망 안이라 지금은 따로 두지 않는다. 망 밖으로 열 일이 생기면 다시 본다.
