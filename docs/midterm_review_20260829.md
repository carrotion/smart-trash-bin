## 2. 병목 재정의 — 문제가 이동했다

**국소(초 단위) 오도메트리는 이제 양호하다.** 동결 해결, 직진 정상, 회전 폐루프
추종 정상. 08-24 시점의 "메인 파이프라인이 조용히 끊긴다"는 문제는 끝났다.

**지배 오차는 장주기 요(방위) 드리프트다.** 두 성분이 실측으로 확인됨:
- 자이로 바이어스 방랑 ~3°/min (항목 4) — 세션이 길수록 선형 누적
- 회전 스케일 오차 × 큰 총회전량 (항목 5) — 많이 돌수록 누적

그리고 **SLAM이 이걸 흡수하지 못했다** — 루프클로저가 두 세션 모두 한 번도 안
걸렸다. `loop_search_maximum_distance: 3.0`은 "SLAM이 믿는 현재 위치" 기준
반경이라, 드리프트가 3m 상당을 넘은 뒤에는 실제로 같은 자리에 돌아와도 후보
탐색 자체가 안 된다.

⚠️ **기록해둘 조언 오류(Remi)**: 2차 매핑 전 "마지막에 시작점으로 크게 돌아오라"고
제안했는데 이는 위 메커니즘상 역효과였다(돌아올 때쯤엔 이미 탐색 반경 밖 +
그 사이 회전량만 증가). "작은 루프를 자주"가 이론상 맞지만 **이것도 아직
가설이다 — 아래 계획의 재생 실험으로 검증할 것.**

병진(거리) 오차는 부차적: 직진 시험·엔코더 정합 모두 정상, 08-24의 거리 스케일
가설도 ~2% 수준.

## 4. 재수립된 계획 (순서 + 판정 기준)

1. **매핑 세션 rosbag 상시 녹화 체계** — `tools/record_bag.sh`로 `/scan_raw`,
   `/scan`, `/odom`, `/imu/data`, TF 포함. 이후 SLAM 파라미터 실험을 전부
   재생으로 옮긴다(로봇 반복 주행 불필요). *판정: bag 하나로 slam_toolbox
   오프라인 재생이 도는지.*
2. **rf2o 도입** — jazzy 포크 빌드 → 우선 **비교 로깅만**(`/odom_rf2o` vs
   EKF vs SLAM 보정치, 융합은 안 함) → 요 드리프트가 실제로 줄어드는지 같은
   코스 반복으로 확인 후 EKF 융합 결정. *판정: 10분급 세션에서 최종 map→odom
   yaw 보정 크기가 유의하게 감소하는가.*
3. **루프클로저 실험 (재생 기반)** — 1번 bag으로 `loop_search_maximum_distance`
   등 스윕 + "작은 루프 자주" 주행 패턴 가설 검증. *판정: 루프클로저 발생
   횟수 > 0 + 방 직각도 개선.*
4. **지자기 간섭 재측정** (도크, `mag_motor_interference.py`) → 통과 시 헤딩
   앵커 설계 착수. *판정: 구동 중 방위 편차가 08-17 중앙 장착 때 수준(1° 미만)인가.*
5. **평가 지표 고정** — 같은 코스 반복 + 최종 map→odom yaw 크기 +
   `round_trip_drift.py`(만들어두고 한 번도 안 돌림). 개선 전후를 항상 같은
   자로 잰다.
6. **광류**: 위 도입 트리거 충족 시에만 재검토.

## 5. 전제 조건 · 리스크

- **배터리**: 현재 불량 팩(만충 11.9V). 장시간 매핑 세션은 3단계 전압 경보
  (11.3/10.9/10.6V, 자동정지 포함)가 지켜보고 있으나, 새 팩(3S2P 35E) 도입
  전까지는 10분 이상 세션 뒤 전압 확인 습관 유지.
- **M1 장기 재발**: 오늘 검증은 단기(11분). 문턱·카펫 등 케이블 스트레스가
  반복되는 실사용 조건의 장기 재발 여부는 미확인 — 매핑 세션마다
  `loop_gyro_diag` 로그로 동기화 정지 0건을 계속 확인.
- **자이로 바이어스 방랑**: 시작 시 1회 보정으로는 부족함이 실측됨. 헤딩
  앵커(4번) 전이라도, 정지 구간마다 재보정(ZUPT식 바이어스 갱신)은 소프트웨어만으로
  가능한 보완책 — rf2o와 병행 검토 가치 있음.
