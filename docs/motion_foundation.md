# 주행 기반 설계 — 층별 기본 동작과 합격 기준

2026-09-27 사용자와 합의: **아래층부터 쌓고, 층마다 합격 기준으로 검증한 뒤에만 위층에서 쓴다.**
윗단(Nav2 등)에서 문제가 나면 거기서 땜질하지 않고, 원인이 된 아래층의 기준을 다시 확인하고 고친다.

배경: 09-27 하루 동안 Nav2를 미검증 기본 동작 위에 올렸다가 결함이 차례로 드러났다. 곡선 명령에서 방향 유지
루프가 ±4.4 rad/s로 발진했고, 회전 방향을 뒤집을 때 튀었고, 180° 중 124°만 돈 채 출발했다. 그때마다
윗단에서 막는 방식이었다 — 사용자 지적: "근본을 터치 못하고 겉핥기, 그때그때 현안만 보고 간다".

## 원칙

1. 각 기본 동작은 **숫자로 된 합격 기준**과 **자동 시험 도구**를 갖는다. 한 가지 조건에서만 확인하고 "됐다"고 하지 않는다(속도·방향·전환을 모두).
2. 무엇을 고치든 **회귀 시험 모음**(`tools/motion_suite.py`)을 다시 돌려 다른 동작이 깨지지 않았는지 확인한다.
3. 위층은 아래층의 **검증된 동작만** 조합해서 쓴다.
4. 처음엔 느리고 확실하게(멈춤 → 확인 → 이동). 최적화(속도·연속 주행)는 기반이 다 통과한 뒤.

## 4층 주행 방식 — 멈춤-확인-이동 (1층 통과 후 구현)

1. Nav2 planner에서 목표까지 경로를 받는다(움직임 제어는 쓰지 않음).
2. 경로 앞쪽 0.3~0.5 m 지점 방향으로 **④ 각도 회전** → 멈춤.
3. 그 방향으로 **② 직진** 최대 0.3~0.5 m(충돌 감시 켠 채) → 멈춤.
4. 스캔 안정(0.5 s) 후 위치·장애물 재확인, 경로 다시 받기 → 2로.
5. 목표 근처에서 ② 짧은 직진으로 도착, ④로 도착 방향.

합격 기준: 1 m 앞·뒤·옆, 장애물 돌아 2 m — 도착 오차 ≤ 10 cm·5°, 충돌 0, 도중 회전 최대 ≤ 1.3 × 설정.
속도·연속 주행 최적화(DWB/RotationShim 재사용 여부 포함)는 이 방식이 통과한 뒤.
