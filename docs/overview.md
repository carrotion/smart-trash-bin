# 스마트 쓰레기통 (Smart Trash Bin) — 프로젝트 개요

> **가제**: 스마트 쓰레기통  
> **목적**: 집안 각 방에 배치된 이동형 쓰레기통이 음성 트리거/상태에 따라 집합 장소로 모였다가, 비우기 및 봉투 교체 완료 후 원래 위치로 복귀하는 자율 로봇 시스템  
> **추가 목표**: 기본 이동 기능을 활용한 웰컴, 군무 등 이벤트성 퍼포먼스 동작 학습/재생

---

## 1. 개발 배경

- 풀 오토메이션(쓰레기 분리·압축·배출 등)은 팀의 역량과 시간으로 구현 불가.
- 따라서 **부분적 기능**에 집중: 방마다 쓰레기통이 자율 이동하여 집합·복귀하는 것만이라도 구현.
- 추가로 로봇의 이동 능력을 활용해 **이벤트성 퍼포먼스**(환영, 군무 등)를 학습시켜 재미/홍보 요소를 더함.

---

## 2. 핵심 기능

### 2.1 기본 기능 (필수)

| 기능 | 설명 |
|------|------|
| **방 단위 배치** | 각 방에 1대씩 쓰레기통 로봇 배치. 각자 홈 포지션 보유. |
| **음성 트리거** | 사용자가 음성 명령(예: "쓰레기통 모여")을 내리면 집합 장소로 이동. |
| **집합 이동** | 트리거 시 모든 쓰레기통이 지정된 집합 장소(예: 현관, 다용도실)로 모임. |
| **쓰레기량 감지** | 내부 센서로 쓰레기가 어느 정도 찼는지 측정 → 사람에게 알림. |
| **봉투 교체 완료 감지** | 사람이 비우고 봉투를 교체하면, 완료 신호(센서 + 음성 확인)를 받아 복귀 시작. |
| **개별 복귀** | 완료 신호 후 각 쓰레기통이 자기 방으로 돌아감. |
| **모바일 앱** | 각 방 쓰레기통의 채움 정도, 상태(대기/이동/집합/복귀), 수동 호출 기능 제공. |

### 2.2 추가 기능 (퍼포먼스)

| 기능 | 설명 |
|------|------|
| **웰컴 동작** | 사용자 귀가/음성 트리거 시 여러 쓰레기통이 정해진 동작으로 환영. |
| **군무 / 이벤트 동작** | 미리 정의된 동작 시퀀스(또는 학습된 패턴)를 여러 대가 동시에 수행. |
| **동작 학습** | 모션 시퀀스를 기록·저장·재생하는 수준부터 시작. 필요 시 경량 ML/강화학습 확장 검토. |

## 3. 시스템 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│                        중앙 서버/AI 서버                      │
│  • STT/TTS 및 대화 처리 (또는 외부 API 연동)                   │
│  • 홈 맵 관리, SLAM 병합, 글로벌 경로 계산                    │
│  • 이벤트 동작 시퀀스 저장/스케줄링                           │
│  • 모바일 앱 API                                              │
└──────────────┬──────────────────────────────┬─────────────────┘
               │ MQTT / WebSocket / HTTP      │
               ▼                              ▼
┌──────────────────────┐           ┌──────────────────────┐
│    쓰레기통 로봇 1    │  ...     │    쓰레기통 로봇 N    │
│  • 엣지 MCU(ESP32 등) │           │  • 엣지 MCU(ESP32 등) │
│  • 모터 드라이버      │           │  • 모터 드라이버      │
│  • LiDAR/SLAM 센서    │           │  • LiDAR/SLAM 센서    │
│  • 채움 센서(ToF/초음파)│          │  • 채움 센서          │
│  • 마이크/스피커(옵션)  │          │  • 마이크/스피커       │
└──────────────────────┘           └──────────────────────┘
```

- **중앙 서버**: SLAM 맵 병합, 글로벌 플래닝, AI 처리, 앱 연동.
- **엣지**: 로봇별 센서 데이터 수집, 로컬 장애물 회피, 모터 제어, 음성 감지/명령 송신.
- **통신**: Wi-Fi 기반 MQTT 또는 WebSocket. 필요 시 로컬 메시지 브로커(RabbitMQ/Mosquitto) 사용.

## 7. 고려사항 및 리스크

| 항목 | 내용 |
|------|------|
| **엔코더 핀 태움 위험** | PH2.0 6핀 커넥터의 M+/M-(12V) 핀과 VCC(5V) 핀의 순서 불일치 시 센서 태움. **Fluke 15B+ 멀티미터 도통 테스트 필수**. |
| **전원 강하 리셋** | 모터 기동 시 Inrush Current로 Pi 5 리셋 가능. **3S 배터리 12V ↔ Pololu 5V 5A 동기식 Buck 분리 및 퓨즈(20A, 5A) 독립 배선**. |
| **스위치 용량 부족** | 1~3A 소전류 스위치 사용 시 접점 녹음. **허용 전류 10A 이상의 대전류 메인 스위치 적용**. |
| **멀티 로봇 충돌** | 좁은 복도/현관에서 여러 대가 충돌하거나 교착. 경로 스케줄링/순차 이동 고려. |
| **음성 프라이버시** | 클라우드 STT 사용 시 개인 정보 이슈. 웨이크워드는 엣지에서 처리하고 명령만 서버로 전송 권장. |

### 9.2 퍼포먼스 동작 학습 방향 제안

팀이 "시행착오를 통해 배우는 과정"을 원하므로, **단계적으로 난이도를 올리는 3단계 접근**을 제안.

#### Level 1: 조작 기반 동작 녹화-재생 (즉시 가능)

- 조이스틱, WASD 키보드, 또는 모바일 앱 조종 UI로 로봇을 움직인다.
- 서버가 `[(t, x, y, theta, speed, action), ...]` 형태의軌跡(trajectory)을 기록.
- 재생 시 각 로봇이 시간축에 맞춰 동일 패턴 수행.
- 장점: 바로 결과물이 나옴. 군무의 타이밍/동기화 개념 학습.

#### Level 2: 키프레임 기반 동작 설계 (추천 시작점)

- 사람이 조종한 경로에서 핵심 포즈만 추출(키프레임).
- 서버에서 키프레임 간 보간(interpolation) + 속도 프로파일 생성.
- 여러 대에게 분배: "A는 (0,0)→(1,0)에서 360° 회전, B는 (0,1)→(1,1)에서 360° 회전" 등.
- 장점: 군무를 "구성"하는 느낌. 코드/시각화로 이해하기 쉬움.

#### Level 3: 파라미터 최적화/시뮬레이션 기반 학습 (ML 입문)

- Gazebo 또는 간단한 2D 시뮬레이터에서 여러 로봇의 군무 시뮬레이션.
- 보상 함수: 충돌 회피 + 원하는 형태 유지 + 에너지 효율.
- 유전 알고리즘, CMA-ES, 또는 강화학습(PPO/DQN)으로 동작 파라미터(속도, 회전 각도, 대기 시간) 최적화.
- ATS 서버의 5060 Ti × 2로 소규모 시뮬레이션 학습 가능.
- 장점: "학습"이라는 키워드를 실제로 체감. 단, 현실 이식성(gap)은 관리 필요.

**제안**: Level 1과 Level 2를 병행하여 1~2주 내로 웰컴/간단 군무를 먼저 만들고, Level 3은 별도 실험 과제로 분리.

### 9.3 서버 자원 활용 제안

ATS 서버 사양(12코어 AMD, RTX 5060 Ti × 2, Gemma4 운영 중)을 고려할 때:

- **STT/TTS**: Gemma4가 이미 있으므로, 음성 처리 파이프라인은 서버에서 실행. Whisper 또는 로컬 STT 모델 탑재 검토.
- **SLAM/맵 병합**: CPU 중심. ROS2 노드로 실행.
- **군무 시뮬레이션/학습**: GPU 하나를 학습용으로 할당, 다른 하나는 Gemma4와 공유 또는 분리.
- **컨테이너화**: Docker/Podman으로 서비스 격리. Gemma4와 쓰레기통 서비스가 리소스 충돌하지 않도록 관리.

### 9.4 기타 검토 포인트

- **VSLAM-only 위험**: 조명 변화, 질감 없는 바닥, 장애물 가림 시 성능 저하. 안정성을 위해 바닥/벽에 ArUco 마커를 배치하여 절대 위치 보정. 추가로 VL53L1X로 장애물 긴급 회피.
- **군무 동기화**: NTP 또는 ROS2 시간 동기화로 타임스탬프 맞춤. Wi-Fi 지연(Jitter) 보정 필요.
- **센서 + 음성 복합 확인**: "쓰레기통아 다 했어?"라고 물으면, ToF가 비어 있음을 확인 후 "응, 돌아갈게" 응답 + 복귀. 퍼포먼스 요소로도 활용 가능.
