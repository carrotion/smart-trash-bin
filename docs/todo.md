- **원인 시험**: 같은 측정을 드라이버 deadzone 1000으로 → **0.123/0.116/0.124/0.132/0.151 m/s**. 드라이버가 deadzone을 출력 바닥으로 깔아준다. 1900은 Yahboom 예제의 520 기본값(310=1600, TT=1000~1250)을 검증 없이 쓴 것 → `speed_floor_sweep_20260924_2227.csv`
- deadzone 1000에선 앞축 0.17 / 뒤축 0.08 m/s로 어긋나고 엔코더가 라이다보다 20~30% 덜 읽음(뒷바퀴 끌림). 뒷바퀴 affine(`1.7692x+461.82`)은 deadzone 1900 상태에서 유도한 값이라 함께 무효
- `driver_deadzone` 파라미터 신설(기본 1900 = 현재 동작 유지)
- **도크 deadzone 0 축별 스윕**(`axle_speed_sweep_dz0_20260924.csv`): 앞 1200→0.06(M1만) / 1800→0.40 / 2400→0.80 / 3000→1.13 m/s, 뒤 600~1200 불안정(M3 거의 정지) / 1800→0.23 / 2400→0.44 / 3000→0.63 m/s
  - **PWM 전체 범위는 약 3600**(코드는 1200 가정). 드라이버는 **출력 = deadzone + PWM**(1900+160=2060 → 보간 0.57 vs 도크 실측 0.59)
  - 무부하 실효 데드존 앞 약 1200, 뒤 약 1150. 로봇 최고속도는 뒤 520 한계 약 0.63 m/s(스펙 178rpm 일치)
  - 속도·회전 제어(`max_pwm`, `min_pwm`, `max_wheel_speed`, `turn_kp/ki`, `min_turn_pwm`, 뒷바퀴 affine)가 전부 "1900+0~1200" 단위 위에 있다 → 함께 재설계
- **다음(제안)**: deadzone을 0 근처로 내리고 축별 PWM→속도를 도크(무부하)에서 데드존까지 재측정 → 축별 피드포워드 + **엔코더 기반 축별 속도 폐루프**(부하·전압·모터 차이를 자동 흡수) → 바닥에서 명령=실제 확인
- **속도 제어 모드 구현(`control_mode: velocity`, 기본값은 아직 `legacy`)**: 드라이버 deadzone 0 + 바퀴별 피드포워드 + 엔코더 속도 PI + 자이로 각속도 PI. 오프라인 시뮬(부하 데드존 1500)에선 0.05~0.4 m/s 추종, 제자리 회전 배분, 폭주 감지·엔코더 끊김 대비 확인
- **도크 실물 시험에서 막힘 — M4(오른쪽 뒤) 엔코더 오카운트 발견**:
  - 직진 0.4 m/s는 목표 근처(0.35~0.41). 저속은 걸림(스틱-슬립)으로 거칠다(도크 무부하라 바닥과 다를 수 있음)
  - 회전 시험 때 M4가 목표와 반대로 읽혀 **폭주 감지가 작동해 정지·잠금**(의도대로)
  - 제어기 없이 시리얼 직접 구동(deadzone 0): 회전 패턴 저출력에서 M4가 **초당 약 22,000카운트(−1.9 m/s)** 로 3초간 일정하게 읽힘 — 520 무부하 최고 0.63 m/s보다 3배 빠른 **물리적으로 불가능한 값**. M4 단독 1200은 처음 0.6초 역방향으로 읽히다 정상
  - 채널 단독 시험(deadzone 1900+300, 높은 듀티)에선 M4 정상, M3 단독 구동 시 M4 변화 0 → 신호 혼선 가설은 기각
  - 재장착 후 재시험(22:5x): 그대로. **고출력 회전 패턴에서도 발생**(−1.84→−0.37 m/s로 감소) → "저듀티에서만" 가설 기각. 직진(모두 같은 방향)은 정상. 공통점은 M3 역방향·M4 정방향인 회전 패턴. 초당 약 22,000카운트는 520 최대(약 7,300카운트/초)의 3배 → 신호 노이즈로 추정. 사용자 손 확인: M3·M4 뻑뻑함 차이 없음 → M3 장착부 걸림 가설은 약화
  - ⚠️ legacy 운용에도 영향 가능: 고출력 회전에서도 나오므로 회전 중 M4 카운트가 오도메트리를 오염시켰을 수 있다
  - **다음: 드라이버 쪽 M3↔M4 커넥터 맞바꿔 시리얼 직접 시험** — 오독이 모터를 따라가면 모터/케이블, 채널 4에 남으면 드라이버 입력
  - (이전 추정) 저듀티 PWM + 다른 채널 동시 구동 때 M4 엔코더 선에 노이즈 유입 또는 커넥터 접촉 불량. **다음: M4 엔코더 커넥터(모터 쪽·드라이버 쪽)와 모터 전원선과의 배선 경로 확인 → 같은 시험 재현(`m4_trace` 패턴)**
  - 부수: 같은 PWM에서 M3가 M4보다 36% 느림(1900+300: 4911 vs 7636), deadzone 0 스윕에선 M3가 800~1200에서 거의 정지 → M3 위치의 마찰/걸림(모터 교체 전에도 M3 자리가 뻑뻑했음). 손으로 M3·M4 돌려 비교 필요
- **8/29 충돌과의 연결**: Nav2가 0.04 m/s를 가정할 때 실제 0.4 m/s — 확인된 사실. 충돌 원인인지는 #15에서 다른 후보와 함께 판단
