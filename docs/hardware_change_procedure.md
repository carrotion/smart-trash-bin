# 하드웨어 변경 작업절차

부품을 교체·이설·재배선하거나 배터리를 바꿀 때 **이 문서를 위에서부터 따라간다.**
자동으로 확인할 수 있는 항목은 `tools/hw_preflight.py`가 한 번에 검사한다.

## 왜 이 문서가 있나

이 프로젝트의 사고 상당수는 "하드웨어를 바꿨는데 거기에 묶인 값이 조용히 틀린 채로
남은 것"이었다. **에러가 안 나서 몇 주씩 버틴다.** 예:

- 라이다를 뒤집어 달았는데 `laser_scan_dir`를 안 바꿔 지도가 거울상 (08-17)
- IMU TF가 없어서 EKF가 몇 주간 자이로를 통째로 버림 (08-29)
- 커넥터를 고쳐 마찰이 줄자 저속 PWM 보정이 전부 낡아 명령의 2~5배를 주행 (08-29)
- 뒷바퀴 교체 재배선 후 매핑을 7곳 중 일부만 고쳐, 정밀이동 도구가 거리를 1/34로 읽음 (09-24)

각 절차 항목 끝의 `(MM-DD)`는 그 규칙을 만든 사건 날짜다. 사건 상세는 `CLAUDE.md`와
`docs/hardware_inventory.md` 변경 이력에 있다.

## 0. 모든 하드웨어 작업 공통

### 작업 전
- [ ] `docs/hardware_inventory.md`를 **먼저 읽는다** — 기억이나 옛 구매목록으로 판단하지 않는다 (08-20, 08-21: 이미 있는 부품/배선을 모르고 틀린 배선 안내)
- [ ] 파이를 **정상 종료**한 뒤 작업한다 — `sudo systemctl poweroff`. 켜진 채로 전원을 뽑지 않는다 (08-16: 강제 차단이 ext4 손상을 만듦)
- [ ] 케이블을 묶거나 고정할 때 **커넥터에 장력이 걸리지 않게** 여유(스트레인 릴리프)를 둔다 (09-24: 고정 작업 중 모터드라이버 USB-C가 두 번 빠짐)

### 작업 후 — 전원 켜고 바로
```bash
python3 tools/hw_preflight.py
```
이 스크립트가 아래를 확인한다. 하나라도 ❌면 다음 단계로 가지 않는다.
- [ ] USB 장치 인식 — CH340(모터, `1a86:7522`) + CP2102(라이다, `10c4:ea60`), `/dev/motor`·`/dev/lidar` 링크 (09-24)
- [ ] 상시 서비스 전부 active — 특히 `smart-trash-diff-drive`가 `activating`에서 멈춰 있으면 모터 포트 문제
- [ ] TF `base_link→imu_link` 존재 (08-29)
- [ ] 센서 값이 **실제로 변하는지** — 주기(Hz)만으로는 살아있다는 증거가 아니다 (08-17: 자기센서가 멈춘 값을 50Hz로 계속 발행, 자기필터가 빈 채로 스캔 통과)
- [ ] 배터리 전압/등급 발행 중(`/battery_tier`)
- [ ] `tools/wheel_config.py`와 `diff_drive_node` 파라미터가 일치 (09-24)
- [ ] **diff_drive 자이로 바이어스가 정상**(|값| < 0.03 rad/s, 정상 범위 -0.011~+0.013). 노드는 **뜨는 순간** 바이어스를 잰다 — 커넥터를 다시 꽂는 순간 노드가 떴고 사람이 로봇을 만지던 중이면 움직임이 바이어스로 박힌다. 이상하면 로봇을 가만히 두고 `sudo systemctl restart smart-trash-diff-drive` (09-24: -0.438로 잡혀 도크에선 오른쪽 바퀴 역전, 바닥 직진 -51°. 이제 노드가 스스로 거부·재측정하지만 preflight가 한 번 더 본다)

## 1. 모터 · 기어박스 · 바퀴 · 모터 배선

### 안전 수칙 (항상)
- 바퀴가 **허공에 뜬 도크 위**에서, **배터리 커넥터에 손이 닿는 상태**로 (08-14)
- `$mtype:3#` / `$mtype:4#` **절대 금지** — TT 프리셋은 정지 명령이 안 먹는다 (08-14)
- 드라이버에 직접 명령할 땐 `$pwm:`만. `$spd:`와 섞지 않는다 (08-14)
- 시리얼 직접 접근 전엔 `sudo systemctl stop smart-trash-diff-drive` — 노드가 포트를 쥔 채 다른 프로세스가 열면 명령이 깨진다(`fail,Command not found!`) (09-24)

### 절차
1. [ ] **4채널 개별 구동** — `python3 tools/motor_channel_test.py --pwm 250 --sec 1.2`
   전 채널 반응, 크로스토크 없음, 정지 후 고정. **한 채널만 고쳤어도 4개 다** 돌린다 (08-20: M1을 고친 뒤 M4가 죽어 있었는데 안 돌려봐서 며칠을 잘못된 데이터로 보냄)
2. [ ] **채널↔바퀴 위치 매핑** — 채널별로 어느 바퀴가 도는지 눈으로 확인. 재배선하면 바뀔 수 있다 (09-24: 좌/우 묶음이 앞/뒤 묶음으로 바뀜)
3. [ ] **방향** — 채널별 양수 PWM이 전진인지 5초씩 개별 구동하며 눈으로 확인 (09-24: 오른쪽 두 채널이 반대로 배선됨)
4. [ ] **엔코더 부호** — 전진할 때 채널별 원시 카운트가 늘어나는지 줄어드는지
5. [ ] **매핑·부호·상수를 전부 갱신** — 아래 "부록 A"의 모든 위치를 **같은 커밋에서**. `hw_preflight.py`로 일치 확인
6. [ ] **새 모터 종류면 카운트/회전 실측** — 바퀴를 손으로 정확히 10회전, `/wheel_encoders` 전후 차이 ÷ 10. 검산: `11펄스 × 4(쿼드러처) × 감속비` (08-15, 09-24). 이후 줄자 대조로 주행 보정(08-15에 raw 899.1 → 주행 보정 857.2)
7. [ ] **무효가 된 보정값 리셋/표시** — 배선·마찰·모터가 바뀌면 아래는 전부 낡는다 (08-29: 커넥터 수리로 마찰이 줄자 명령의 2~5배를 주행)
   - `motor_pwm_offset_m1..m4` — 특정 채널의 특정 모터 마찰 기준값. 매핑이 바뀌면 엉뚱한 바퀴에 적용된다 → **0으로 리셋**
   - `straight_trim`, `min_pwm`, `max_wheel_speed`, `turn_kp/ki`, `min_turn_pwm`, `precise_move.py`의 `COAST_K` → **재측정 대상으로 표시**
8. [ ] **종류가 다른 모터가 섞이면 축별 PWM→속도 곡선** — `python3 tools/axle_speed_sweep.py` (도크). 데드존까지 **내려가며** 잰다 — 임의로 자른 구간만 재면 그 밖을 모른 채 모델을 만든다 (08-19). 두 곡선이 원점을 안 지나면 배율이 아니라 기울기+절편으로 맞춘다 (09-24)
9. [ ] **바닥 직진** — `python3 tools/straight_check.py --trials 4 --speed 0.2 --json docs/calibration/straight_check_YYYYMMDD.json`
   통과 기준: 전진·후진 이탈각 부호 반대·크기 대칭, 채널별 이동거리(m) 90% 이상
10. [ ] **제자리 회전 재캘리브레이션** — `python3 tools/rotation_calibrate.py` (바닥). 피드포워드가 바뀌면 게인도 반드시 재튜닝 (08-19: 안 하면 진동)
11. [ ] **코스팅 재측정** — `python3 tools/coast_sweep.py <속도>` 여러 속도 → `precise_move.py`의 `COAST_K` 갱신 (08-29)
12. [ ] **속도 스케일** — 명령 속도와 실제 속도가 맞는지(`calibrate_drive.py`, 줄자)

## 6. 측정 위생 (모든 시험 공통)

- [ ] **시험 중엔 아무도 대시보드로 조종하지 않는다** — 대시보드는 버튼을 누를 때만 `/cmd_vel`을 발행한다(대기 중 15초간 0개 실측, 09-24). 확실히 하려면 `sudo systemctl stop smart-trash-motor-dashboard smart-trash-map-dashboard`
- [ ] **이상한 결과가 나오면 원인 후보를 "그때 바뀐 것" 하나로 좁히기 전에 시간순으로 적는다** — 09-24에 "대시보드를 끄니 정상"이라고 결론냈지만, 실제로는 그 직전에 diff_drive를 재시작했고 재시작 직후(대시보드 켜진 채) 이미 정상이었다. 진짜 원인은 재시작으로 사라진 자이로 바이어스 오류였다
- [ ] **로봇이 실제로 어디 있는지 확인** — 도크인지 바닥인지 사람에게 묻는다. 가정하고 주행 명령을 보내지 않는다 (08-29: 도크라 가정했다가 충돌)
- [ ] 주행 전 `/scan`으로 **전후방 여유** 확인
- [ ] 도크 = 채널·방향·무부하 곡선용 / 바닥 = 직진·회전·오도메트리·코스팅용
- [ ] **"모터가 돌았다"는 엔코더로 확인** — 안 돌았어도 "간섭 없음" 같은 결과가 나온다 (08-17)
- [ ] 측정값과 함께 **배터리 전압을 기록** — 모터 회전수는 전압에 거의 비례해서 전압 없는 측정값은 비교 불가 (08-19)
- [ ] 결과는 `docs/calibration/`에 CSV/JSON으로 남긴다
- [ ] `diff-drive`만 재시작하면 EKF가 옛 누적값을 들고 있다 — 둘을 같이 재시작 (`python3 tools/mapping_cleanup.py --restart`) (08-16)
