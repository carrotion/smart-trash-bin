## 1. Executive Summary

라즈베리 파이 5 기반 Smart Trash Bin 로봇의 2D LiDAR(LD06) 장착에도 불구하고 발생하던 **전면 충돌(식탁/의자 다리, 소파 밑 등)** 현상에 대해 내부 커밋/실측 로그 및 외부 상용 로봇(Roborock, Roomba, ROS 2 산업용 AGV) 표준 기술을 전수 조사·분석했습니다.

```
[라이다 전면 충돌의 4중 결합 원인 구조]
1. [SW 설정]  Nav2 obstacle_min_range(0.11m) 기준점 오류 ──> 전방 5.4cm 구간 코스트맵 마킹 원천 차단 (Remi 규명·수정 완료)
2. [광학 기하] LD06 각분해능(0.79°) vs 얇은 기둥(2cm) ──> 1m 거리에서 빔 간격(1.4cm)으로 인한 1프레임 스캔 누락(Dropout)
3. [높이 한계] 2D 라이다 단일 평면(z=8.5cm) 스캔 ──> 소파 돌출부/낮은 의자 다리 받침의 물리적 사각지대 (ToF 필요)
4. [제어 지연] 로컬 코스트맵 클리어링/리셋 시 일시적 장애물 증발 + 10Hz -> 6Hz 제어 주기 지연
                                      │
                                      ▼
                        [즉시 적용 권장 3대 솔루션]
1. nav2_collision_monitor 도입: 코스트맵 우회, 50Hz 라이다 직접 감시 긴급 정지 (<20ms 반응)
2. Costmap Persistence(점속 레이어): 얇은 다리 1프레임 누락 시에도 코스트맵 1.5초간 잔존 유지
3. 맵 제작 분리 워크플로우: 자율탐색(explore_lite) 동시 매핑 중단 ──> 10분 수동 고품질 맵핑 후 AMCL 고정 운용
```

## 2. Remi의 핵심 발견 및 4대 충돌 원인 심층 분석

### 2.1 [원인 1: 규명 완료] Nav2 `obstacle_min_range` 기준점 오류 (Commit `d6490f3`)
* **메커니즘**: `nav2_costmap_2d/obstacle_layer.cpp` 소스 분석 결과, `obstacle_min_range`의 컷오프 기준점은 `base_link`가 아니라 **라이다 센서 원점(`obs.origin_`)**이었습니다.
* **영향**:
  * 라이다는 `base_link` 전방 $5.4\text{cm}$에 장착되어 있고, 로봇 앞범퍼는 `base_link` 전방 $11.0\text{cm}$(라이다 렌즈 앞 $5.6\text{cm}$)에 위치합니다.
  * 기존 `obstacle_min_range: 0.11` 설정은 라이다 렌즈 앞 $11\text{cm}$ (즉, **`base_link` 전방 $16.4\text{cm}$**) 이내의 모든 점을 코스트맵 마킹에서 제외시켰습니다.
  * 결과적으로 **로봇 앞범퍼 앞 $5.4\text{cm}$ 구간 전체가 코스트맵 상에서 완벽한 사각지대(장애물 마킹 불가)**가 되어 전방 충돌의 주원인으로 작용했습니다.
* **조치 현황**: `nav2_params.yaml`에서 `obstacle_min_range: 0.0`으로 정상화 완료.

---

### 2.2 [원인 2: 광학/기하 한계] 얇은 원통형 다리(식탁/의자)의 빔 투과 및 반사 산란
* **각분해능 한계 계산**:
  * LD06 라이다: $360^\circ$당 약 454점 $\to$ 각분해능 $\Delta \theta \approx 0.79^\circ (0.0138\text{ rad})$.
  * 거리 $d$에서의 인접 빔 간격 $s = d \cdot \Delta \theta$:
    * $d = 0.5\text{m} \implies s = 0.69\text{cm}$ (다리당 약 3~4개 빔 적중)
    * $d = 1.0\text{m} \implies s = 1.38\text{cm}$ (다리당 약 1~2개 빔 적중)
    * $d = 1.5\text{m} \implies s = 2.07\text{cm}$ (다리 직경 $\phi 2\text{cm}$보다 넓어 **빔이 다리 사이로 빠져나감**)
* **원통형 금속/원목 다리의 반사 특성**: 원통 표면의 곡률로 인해 레이저 입사각이 측면일 때 빛이 센서로 되돌아오지 않고 난반사되어 거리값이 `inf`로 처리되는 현상(Dropout)이 실측에서 확인됨.
* **코스트맵의 문제점**: 단 1프레임이라도 `inf`가 들어오면 Nav2 `raytrace` 레이어가 기존에 마킹되어 있던 장애물 셀을 즉시 빈 공간(`FREE`)으로 지워버림.

---

### 2.3 [원인 3: 기구적 한계] 2D 평면 라이다의 높이(Z축) 사각지대
* LD06 라이다는 $z \approx 8.5\text{cm}$ 단일 수평면만 스캔합니다.
* **실제 충돌 사례**:
  1. **소파/침대 프레임 밑 (2026-08-21 실측)**: 바닥에서 15~20cm 높이의 상부 돌출부는 라이다 평면(8.5cm)보다 위에 있어 완전히 투과됨 $\to$ 로봇 상판 충돌.
  2. **경사형 의자 다리/받침대**: 바닥에 낮게 깔린 2~3cm 두께의 의자 받침대는 라이다 평면 아래에 있어 감지 불가 $\to$ 바퀴 걸림/충돌.

---

### 2.4 [원인 4: 제어/시스템 지연] 코스트맵 리셋 및 제어 주기 저하
* `Failed to make progress` 발생 시 실행되는 `clear_entirely_local_costmap` 복구 동작이 로컬 코스트맵 전체를 지운 직후, 새 스캔이 코스트맵에 마킹되기 전 수백 ms 사이에 로봇이 재출발하면서 전방 장애물과 충돌.
* 파이 5의 CPU 부하 시 `controller_server` 주기가 $10\text{Hz} \to 6\sim 7\text{Hz}$로 떨어지며 감속 반응 지연.

## 3. 내외부 벤치마크 및 실전 해결 솔루션

### 3.1 [솔루션 1: 최우선 추천] `nav2_collision_monitor` 직접 충돌 방지 도입

코스트맵은 `레이저 수신(10Hz) -> 코스트맵 마킹/인플레이션(5Hz) -> 컨트롤러 궤적 계산(10Hz)`의 3단계를 거치므로 총 지연 시간이 $150 \sim 300\text{ms}$에 달합니다. 

상용 AGV 및 최신 Nav2 표준은 **코스트맵을 거치지 않고 원시 라이다 스캔(`/scan`)을 50Hz로 직접 감시하는 전용 노드(`nav2_collision_monitor`)**를 사용합니다.

```mermaid
flowchart LR
    LIDAR[/scan 라이다 점군/] --> CM[nav2_collision_monitor\n(50Hz 직접 기하 검사)]
    NAV[Nav2 Controller\n/cmd_vel_nav] --> CM
    CM -->|위험 시 즉시 0 감속\n지연 <20ms| MOTOR[/cmd_vel\ndiff_drive_node/]
    
    subgraph Polygons [다중 안전 영역]
        P1[Stop Polygon: 전방 8cm]
        P2[Slowdown Polygon: 전방 25cm]
    end
    Polygons -.-> CM
```

* **동작 원리**:
  1. **정지 영역(Stop Polygon)**: 로봇 앞범퍼 전방 $8\text{cm}$ 내에 단 1개의 라이다 포인트라도 들어오면 즉시 모터 출력을 0으로 차단.
  2. **감속 영역(Slowdown Polygon)**: 전방 $25\text{cm}$ 내 장애물 접근 시 강제 50% 감속.
* **장점**: 코스트맵 리셋, 제어기 렉, 경로 계획 오류와 완전히 독립적으로 작동하는 **100% 하드웨어급 가드레일** 제공 (패키지: `ros-jazzy-nav2-collision-monitor`).

---

### 3.2 [솔루션 2: 알고리즘 개선] 얇은 장애물 잔존 필터 (Costmap Decay & STVL)
* **목적**: 얇은 의자 다리의 1프레임 스캔 누락(Dropout) 시 코스트맵에서 바로 지워지는 문제 방지.
* **방법**:
  * `obstacle_layer`의 `raytrace_max_range`를 `obstacle_max_range`보다 짧게 설정하거나,
  * `ros-jazzy-spatio-temporal-voxel-layer (STVL)`을 적용하여 한 번 감지된 장애물은 1.5~2.0초 동안 레이저 빔이 통과하더라도 메모리에 유지(Decay Model)되도록 설정.

---

### 3.3 [솔루션 3: 하드웨어 보강] ToF 센서 (VL53L5CX 8x8) 또는 물리 범퍼
* **VL53L5CX 8×8 다중 영역 ToF (부품비 ~2만원)**:
  * 전방 $63^\circ \times 63^\circ$ 3D 시야각으로 높이 $0 \sim 30\text{cm}$를 동시 커버.
  * 소파 하부 돌출부, 낮은 의자 받침대를 완벽 감지하여 라이다 높이 사각지대 영구 해소 (`docs/hardware_inventory.md` 2순위 확정 부품).

## 4. 맵 제작(SLAM) 리소스 낭비 방지 및 고효율 워크플로우

현재 프로젝트에서 **"자율탐색(`explore_lite`) + 실시간 SLAM(`slam_toolbox`) + 충돌 회피(`nav2`)"를 동시에 엮어 실물 지도를 만들려고 시도**하면서, 다음 문제들이 상호 중첩되어 막대한 시간과 시행착오가 발생하고 있습니다:

```
[복합 결합으로 인한 디버깅 교착]
자이로 바이어스 방랑 ──┐
엔코더 커넥터 단선 ──┼──> [동시 발생] ──> "원인이 SLAM인가? Nav2인가? 하드웨어인가?" 혼란
코스트맵 사각지대 ──┤
라이다 빔 누락   ──┘
```

### 💡 권장 3단계 맵핑 및 자율주행 분리 전략

```
[Phase 1: 1회성 고품질 수동 매핑 (10분 완료)]
스마트폰/PC 모터 대시보드(수동 조종) ──> '소루프 데이지 체인' 주행 ──> 완벽한 our_home.yaml 맵 저장
                                      │
                                      ▼
[Phase 2: 고정 맵 기반 신뢰성 자율주행 (Nav2 AMCL)]
정적 맵(our_home) 로드 ──> AMCL 위치추정 (자이로 누적 오차 0) ──> Waypoint 자율주행 검증
                                      │
                                      ▼
[Phase 3: 안전한 미지의 영역 자율탐색 (Explore)]
nav2_collision_monitor 가드레일 활성화 ──> explore_lite 복귀
```

1. **Phase 1 (수동 10분 맵핑)**: 
   * 자율탐색을 끄고, 수동 원격 조종으로 집 안을 10분간 천천히 주행(방마다 1바퀴 소루프 닫기)하여 왜곡 없는 기준 지도(`clean_map`)를 1회 제작 및 파일로 저장합니다.
2. **Phase 2 (정적 맵 기반 Nav2 항법)**:
   * SLAM을 끄고 `AMCL` 위치 추정 모드로 전환합니다. 이미 완성된 지도가 있으면 자이로 드리프트가 있어도 파티클 필터가 라이다 벽면 매칭으로 위치를 매초 자동 보정하므로 누적 오차가 0이 됩니다.
3. **Phase 3 (충돌 방지 가드레일 결합 후 자율탐색)**:
   * `nav2_collision_monitor`를 활성화하여 전방 충돌이 물리적으로 불가능한 상태를 만든 후 자율 탐색(`explore_lite`)을 재개합니다.
